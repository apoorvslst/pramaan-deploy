SECTION 1: DESIRED USER FLOW (THE TRUTH)
================================================================================

--- BIDDER FLOW ---
1. Bidder opens the app -> sees Auth Page (login/register)
2. Bidder registers: name, email, password, company name, entity type, phone
   NO PAN/GSTIN at registration (they go in KYC step after login)
3. Bidder logs in -> JWT token stored in localStorage as 'praman_token'
4. After login, if isKycVerified === false, app shows KYC tab automatically.
   Bidder CANNOT access tenders without completing KYC.
5. KYC Screen: Bidder uploads Aadhaar (file), PAN card (file), enters PAN number,
   GSTIN (optional), Udyam number (optional), GEM Seller ID (optional).
   -> Calls POST /api/auth/kyc/verify with Bearer token + form data.
   -> Backend validates, calls Groq AI for cross-document identity check.
   -> Marks isKycVerified=true in MongoDB User record.
   -> Frontend updates localStorage user with isKycVerified=true.
   -> Redirects Bidder to "Available Tenders" tab.
6. Bidder sees list of PUBLISHED tenders: GET /api/tenders?status=PUBLISHED
7. Bidder clicks a tender -> fills bid details + uploads documents
   (GST cert, Udyam, PAN, CA Turnover cert, Debarment Affidavit)
   -> POST /api/bids/submit (multipart form)
   -> Shows "Bid Submitted! Your Bid Reference: BID-2026-XXXXXX"
8. "Activity Center" tab -> GET /api/bids/my-submissions (Bearer token)
   Shows each bid: Tender title, Bid Ref, Status, Date.
   Status polled every 30s OR updated via Socket.io 'OFFICER_DECISION_RECORDED'.
9. "Tender History" tab: Timeline view of all submitted bids.

--- OFFICER FLOW ---
1. Officer opens app -> Auth Page -> logs in -> JWT stored.
2. After login -> Officer Dashboard with Sidebar navigation.
3. Dashboard: Live stats from GET /api/tenders and GET /api/bids.
4. Tender Management (/tenders):
   - List of officer's own tenders (filter by createdBy).
   - "Create New Tender" button -> form with: Title, Department, Value INR, Closing Date, Category, Requirements.
   - "Get AI Suggestions" button -> POST /api/tenders/ai-assist (Groq AI returns recommended params).
   - AI suggestions pre-fill form fields.
   - "Create Tender" -> POST /api/tenders -> status: DRAFT
   - "Publish" button on each tender -> PATCH /api/tenders/:id/publish -> status: PUBLISHED
   - PUBLISHED tenders appear in Bidder portal immediately.
5. Bid Review (/bidders):
   - GET /api/bids shows all bids received on officer's tenders.
   - List: Bidder name, Tender title, Status, Compliance Score, Date.
   - "View" button -> navigates to /evidence/:bidId (3-Pane Evidence Viewer).
6. 3-Pane Evidence Viewer (/evidence/:bidId):
   Pane 1: Document Viewer - lists uploadedDocuments from BidSubmission.
   Pane 2: Extracted Data - bidder details from Bidder model (GSTIN, PAN, Company Name).
   Pane 3: AI Verification Result - complianceScore, riskLevel, aiRecommendation.
   - "Run AI Verification" button -> POST /api/verification/:bidId/verify (Groq AI)
   - Returns scores, displayed in Pane 3.
7. Comparison View: All bids for a tender ranked by score.
   -> GET /api/verification/tender/:tenderId/evaluations
   -> Ranked table: Rank, Bidder, Score, Risk, AI Recommendation, Decision
8. Officer Decision: "Qualify" or "Disqualify" button on each bid.
   -> POST /api/verification/:bidId/decision
   -> If overriding AI, justification is mandatory (enforced backend).
   -> Decision recorded, Socket.io emits to tender room.
   -> Bidder Activity Center updates in real-time.

--- BUG #10: Idempotency guard may block all POST requests ---
FILE: backend/middlewares/chaos.js (idempotencyGuard function)
ROOT CAUSE: If idempotencyGuard returns 400 when X-Idempotency-Key header is missing,
  ALL API calls from the frontend (which don't send this header) will fail with 400.
FIX: In chaos.js, find the idempotencyGuard middleware and change it to:
  export const idempotencyGuard = (req, res, next) => {
    // Make idempotency key optional — just log if missing, don't reject
    if (['POST', 'PUT', 'PATCH'].includes(req.method)) {
      const key = req.headers['x-idempotency-key'];
      if (!key) {
        // Just log, don't block
        console.log(`[Idempotency] No key on ${req.method} ${req.path}`);
      }
    }
    return next();
  };

SECTION 4: BACKEND API REFERENCE
================================================================================

AUTH:
  POST /api/auth/register  { name, email, password, role, organization, department, phone }
  POST /api/auth/login     { email, password } -> { token, user }
  GET  /api/auth/me        Bearer -> { user }
  POST /api/auth/kyc/verify Bearer + { panNumber, gstinNumber?, udyamNumber?, gemSellerId?, documents: [{docType, name}] }

TENDERS:
  GET  /api/tenders         ?status=PUBLISHED -> { tenders: [] }
  POST /api/tenders         Bearer(OFFICER) + { title, department, estimatedValueINR, closingDate }
  PATCH /api/tenders/:id/publish  Bearer(OFFICER)
  POST /api/tenders/ai-assist     Bearer(OFFICER) + { title, department, estimatedValueINR, category, requirements }

BIDS:
  POST /api/bids/submit          Bearer(BIDDER) + multipart: { tenderId, files... }
  GET  /api/bids                 Bearer -> { bids: [], submissions: [] }
  GET  /api/bids/my-submissions  Bearer(BIDDER) -> { submissions: [] }
  GET  /api/bids/tender/:tenderId Bearer(OFFICER) -> { submissions: [] }
  GET  /api/bids/:id             Bearer -> { submission }

VERIFICATION:
  POST /api/verification/:bidId/verify         Bearer(OFFICER) -> runs Groq AI pipeline
  GET  /api/verification/:bidId/evidence       Bearer -> { evidenceList, evaluationResult }
  POST /api/verification/:bidId/decision       Bearer(OFFICER) + { decision, officerJustification }
  GET  /api/verification/tender/:tenderId/evaluations  Bearer(OFFICER) -> { rankedBidders: [] }
